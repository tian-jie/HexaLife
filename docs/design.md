# HexaLife 技术设计
**产品名：Virus Spreading Simulator / 病原世界**
**内部代号：HexaLife**

> 功能规则以 `docs/specs.md` 为准。本文只写实现方案。

---

## 1. 架构总览

**Rust 原生算，Tauri 前端看。模拟本身单线程，另用一条线程避免堵住界面。**

```text
┌──────────────────────────────────────────┐
│ Tauri Application                         │
│                                          │
│  模拟线程（唯一修改世界的地方）             │
│     │ 统计 JSON + 当前视野的像素缓冲       │
│     ▼                                    │
│  WebView：画视野、按钮、统计、悬停查询      │
└──────────────────────────────────────────┘
```

原则：

- 模拟状态只存在于 Rust 的模拟线程。
- 前端保存相机位置和最近一帧画面，不保存生命数组。
- 默认地图是 10000×10000 格、1 亿人。不传输整张地图，也不逐格推送增量。
- 刷新时只传当前视野的聚合像素，以及全图统计。
- 速度滑块是等待上限。一天算不完时，算完就进入下一天。

---

## 2. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 计算核心 | Rust，模拟逻辑单线程 | 随机流有固定顺序，不能并行打乱 |
| 应用外壳 | Tauri v2 | 计算放在原生进程，内存不受页面限制 |
| 前端 | TypeScript + Vite | 只负责画面和控制 |
| UI | 原生 DOM | 按钮和统计面板，不引入前端框架 |
| 渲染 | Canvas 2D | 画的是视野像素，不是 1 亿个六边形 |
| 配置 | TOML | Rust 读取方便 |
| 随机数 | `rand::rngs::StdRng` | 可播种的标准伪随机生成器 |
| 通信 | Tauri command + Channel 二进制 | 视野像素不走 JSON |

本阶段不实现单步、曲线、参数面板、CSV 和地图快照。

## 4. 世界状态存储

### 4.1 坐标

- 格子编号 `index = r * width + q`。
- 邻居和距离按规格的轴向公式当场计算，不建 1 亿格的邻居表。
- 六个方向减出来的坐标只要有一个越界，该邻居就不存在。

### 4.2 人

每个人占固定槽位，死亡后槽位留空，编号不回收。出生时追加到数组末尾。

```rust
struct Person {
    cell: u32,
    home: u32,
    next_in_cell: u32,     // 同格链表，u32::MAX 表示结尾
    infected_on: u32,      // 仅感染有效
    immune_until_day: u32, // 免疫在该天开始时结束；仅免疫有效
    state: u8,             // 0 健康 / 1 感染 / 2 免疫 / 3 死亡槽位
    generation: u8,        // 0、1、2、3 表示 3+
}
```

约 20 字节一名生命。1 亿人约 2GB。自然死亡和病毒死亡留下的槽位会继续占内存；按默认概率跑满 10000 天，量级仍在数 GB 内。

`alive: Vec<u32>` 保存存活编号。死亡时从格子链表摘除，并从 `alive` 交换删除。遍历一天的存活者时按编号排序后的顺序处理；`alive` 在每次阶段开始前按编号升序使用。出生只追加编号，不把新编号插进当天已经开始的阶段。

### 4.3 格子与分块计数

不给每个格子分配 `Vec`。

| 结构 | 规模 | 作用 |
|---|---|---|
| `cell_head: Vec<u32>` | 1 亿个 `u32`，约 400MB | 该格第一名生命，空格为 `u32::MAX` |
| `tiles` | 100×100 格一块，默认地图 100×100 块 | 每块的健康、感染、免疫人数 |

人进入、离开、出生、死亡或改变状态时，同时改格子链表和所在块的三项计数。链表摘除只扫描该格的人。默认密度下每格通常是个位数到几十人。

全图三项计数由各块相加得到，统计面板不扫描 1 亿人。

### 4.4 阶段辅助结构

| 结构 | 用途 |
|---|---|
| `active_infected: Vec<u32>` | 当天开始时已处于传染日的人 |
| `immune_expiring: Vec<Vec<u32>>` | 下标是到期日，到期日当天开始时变回健康 |

新感染者进入下一天才会加入 `active_infected`。免疫者在转为免疫时登记到 `immune_until_day` 那一桶。

## 5. 初始人口

按规格做两级抽样，总人数精确等于 `initial_population`：

1. 背景总权重 = `λ_bg * width * height`。
2. 每个中心只在 `ceil(truncation * σ)` 的窗口内累加权重，越界位置不加。
3. 为每个中心的窗口建别名表。
4. 对生命编号 `0..initial_population` 依次：先抽来源，背景则均匀抽格，中心则查该中心的别名表。

这一步只用模拟线程上的 `StdRng`。生成结束后做一次断言：存活人数等于配置值。

## 6. 模拟线程

### 6.1 线程

主线程负责窗口和 command。模拟线程独占 `World` 和 `StdRng`。控制命令经 `crossbeam-channel` 进入模拟线程。

```rust
enum Control {
    Start,
    Pause,
    Resume,
    Reset,
    SetSpeed(f32),
    SetCamera(Camera),
    Shutdown,
}
```

`Start` 和 `Reset` 都在模拟线程里读配置文件。command 不携带配置正文。

### 6.2 主循环

```text
loop {
    处理已经到达的控制命令

    if running {
        开始计时
        world.tick()
        if 距离上次推送已达到刷新间隔 {
            按最新相机生成视野像素
            推送像素和全图统计
        }
        若已完成 maxDays：running = false，进入暂停
        elapsed = 本天耗时
        if 不是最快档 && elapsed < 1/speed {
            sleep(1/speed - elapsed)
        }
    } else {
        阻塞等待下一条控制命令
    }
}
```

- `SetSpeed` 只改下一次等待的上限。
- 最快档不 sleep。
- 刷新可以跳过中间画面，不能跳过 `tick`。
- 暂停时线程阻塞，不空转。

### 6.3 开始与重置

两者都读取 `config/default.toml`，缺项用代码里的默认值补齐，然后校验。

- 开始失败：保持未开始，向前端发送错误文本。
- 重置失败：不替换 `World`，维持原来的运行或暂停状态，向前端发送错误文本。
- 成功：用新种子新建 `StdRng`，生成 `T = 0` 的世界，进入运行，并立刻推送一帧视野和统计。

## 7. 单日流程

顺序与规格第 5 节相同。

1. **免疫到期**：取出当天的到期桶，状态改为健康，更新分块计数。
2. **移动**：按编号升序遍历本步开始时的存活者。新生儿不在这个集合里。感染者是否移动看配置。移动时从旧格链表摘到新格，两个块的计数都要改。
3. **传播**：用移动完成后的位置。传染源只包括本步开始时处于传染日的人。目标按编号升序，每个目标的感染者再按编号升序做命中。新感染者写入状态和 `infected_on = 今天`，当天不进入传染源列表。
4. **自然死亡**：仍按本步开始时的存活名单、编号升序。死亡者改成死亡槽位，移出链表和 `alive`。
5. **病毒死亡与康复**：只处理本步开始时处于传染日、且没有在上一步自然死亡的人。
6. **出生**：按本步自然死亡之后仍然存活的编号升序判定。新生儿追加到数组末尾，状态为健康，常住点为出生格。当天后续逻辑不再访问他们。
7. **统计**：用分块计数汇总全图。分代病毒死亡用单独计数器，不扫全图。

同一天的随机数都从这一条 `StdRng` 顺序取出。

## 8. IPC

### 8.1 前端到 Rust

```rust
fn start()
fn pause()
fn resume()
fn reset()
fn set_speed(speed: f32)
fn set_camera(camera: Camera)
fn query_cell(q: u32, r: u32) -> CellCounts
```

`query_cell` 由模拟线程读取该格链表并返回健康、感染、免疫人数。相机变化不读配置，也不消耗随机数。

### 8.2 Rust 到前端

| 数据 | 内容 | 时机 |
|---|---|---|
| `stats` | 规格第 8 节的当日统计，外加运行状态和错误文本 | 每次画面刷新，以及开始、重置、自动暂停 |
| `view` | 当前视野的 RGBA 缓冲 | 与 `stats` 同一刷新节拍 |

视野缓冲：

```text
[width: u16][height: u16]
[RGBA: u8 × width × height × 4]
```

默认视野缓冲不超过 1024×1024。一个像素覆盖一个矩形格块。Rust 用分块计数或格内链表求出该像素内的总人数和感染人数，再按规格第 2 节着色。缩小到能看全图时，一个像素覆盖多块，只加块计数，不遍历人。放大到一格一像素时，只遍历视野内的格子链表。

前端不保存 1 亿格的状态镜像。新的一帧直接替换上一帧像素。

悬停时，前端把鼠标位置换算成 `(q, r)`，调用 `query_cell`。换算落在矩形外则不查询。

## 9. 渲染

平面轴向坐标投影到像素：

```text
x = size * sqrt(3) * (q + r / 2)
y = size * 1.5 * r
```

这个公式只用于决定视野覆盖哪些格，以及悬停时把鼠标换回坐标。真正上屏的是已经着好色的视野缓冲，不是逐个六边形描边。

图例四项：黑色无人，绿色为健康或免疫，黄色到红色表示感染占比升高，同一色相下越亮表示总人数越多。

平移和缩放只改 `Camera`：中心格、每个像素覆盖的格数。拖动和滚轮通过 `set_camera` 送给模拟线程，下一次刷新生效。

## 10. 前端状态机

```text
Idle → Running ⇄ Paused
Reset 成功：无论原来是 Running 还是 Paused，都进入新的 Running
到达 maxDays：Running → Paused
```

| 状态 | 开始 | 暂停 | 继续 | 重置 | 速度 |
|---|---|---|---|---|---|
| Idle | 可用 | 禁用 | 禁用 | 禁用 | 可用 |
| Running | 禁用 | 可用 | 禁用 | 可用 | 可用 |
| Paused | 禁用 | 禁用 | 可用，但已到最大天数时禁用 | 可用 | 可用 |

按钮显示可以先随点击变化，最终以 Rust 推送的运行状态为准。配置错误显示在统计面板附近，不弹系统对话框。

## 11. 配置

文件：`config/default.toml`。只有开始和重置读取它。

```text
[map]        width、height
[initial]    initial_population、感染人数、位置模式、格子编号、seed
[density]    lambda_bg、truncation、人口中心列表
[disease]    D、N、各代总感染率、各代总致死率
[vital]      birth_rate_per_day、natural_death_rate_per_day
[movement]   三类概率、距离、tau、beta、感染期是否可移动
[ui]         速度范围、默认速度、刷新间隔毫秒、C_bright
[sim]        max_days
```

校验失败的规则与规格第 9 节相同。缺省键用默认值。未知键忽略。不把非法值改成默认值后再继续跑。

## 13. 实施顺序

**阶段一：小地图跑通一天**

- 坐标、精确放置、移动、传播、两种死亡、出生、免疫。
- 测试配置使用很小的 `width`、`height` 和 `initial_population`。
- 断言人数、父代、发病日和随机种子可复现。

**阶段二：默认规模**

- `cell_head`、分块计数、`StdRng` 顺序。
- 开始、暂停、继续、重置、速度上限、最大天数。
- 视野缓冲、平移缩放、悬停查询、统计面板。

阶段一的测试不代替默认 10000×10000 的生成和一帧视野。阶段二至少在默认配置下完成人口放置，并画出一帧全图缩略视野。

## 14. 关键决策

| 决策 | 选择 |
|---|---|
| 地图 | 平面六边形矩形，默认 10000×10000 |
| 人与格 | 人是数组，格是链表头，一格可以有 0 到多人 |
| 初始人数 | 配置里的精确值，默认 1 亿；密度只是抽样权重 |
| 邻居 | 坐标现算，不存邻居表 |
| 随机数 | 一条 `StdRng`，种子来自当次开始或重置 |
| 画面 | 视野像素和分块汇总，不传整图 |
| 速度 | 等待上限；算得慢就按实际耗时走 |
| 参数 | 开始读一次，重置读一次 |

## 15. 风险与对策

| 风险 | 对策 |
|---|---|
| 1 亿人加上格子头，内存约 2.5GB，死亡槽位还会涨 | 人结构保持紧凑；测试用小地图。默认规模要求机器有足够内存 |
| 全图感染后，一天要处理大量接触判定，做不到 60 天/秒 | 速度只作为上限；最快档不 sleep |
| 若每帧扫描全图，界面会卡死 | 缩小看块计数；放大只扫视野内的链表 |
| 重置读到坏配置 | 保留旧世界，只显示错误 |
| 链表摘除在极密格子上变慢 | 先接受线性扫描。默认峰值权重下单格人数有限 |
